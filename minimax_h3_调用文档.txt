minimax_h3 调用文档（snumom）
============================

二、怎么调
----------
创建  POST https://snumom.com/v1/videos
查询  GET  https://snumom.com/v1/videos/{id}
下载  GET  https://snumom.com/v1/videos/{id}/content

三个接口都要带：
  Authorization: Bearer sk-你的Key
创建还要：
  Content-Type: application/json

创建成功返回 id（如 task_xxx）。用这个 id 轮询，不要拿上游的 task-xxx 来查网关。
status：
  queued / in_progress / unknown  = 还在排队或生成（unknown 不是失败）
  completed                       = 成功；视频在 metadata.url，或 GET .../content
  failed / error                  = 失败，预扣会退

1080P 排队几分钟到十几分钟都正常。


三、请求字段
------------
model / prompt / size  必填
seconds  可选，4～15；JSON 里写 5 或 "5" 都可以。不传 = 5 秒
size     宽x高。请直接用第四节表格（计费按表内比例识别）
         允许：1:1  2:3  3:2  3:4  4:3  9:16  16:9  21:9
         只传 size，不要再传 resolution、aspect_ratio
         minimax_h3-768p 只能用 768P 列的 size，传 1080P 的 size 会 400
         minimax_h3-1080p 用 1080P 列

参考（可选）：
  图≤9  视频≤3（每条2～15秒）  音频≤3（每条2～15秒）  合计≤12
  URL 必须是公网 http/https，端口只能 80 或 443
  只用下面三个字段，不要再写 images / input_reference / input_references / image
  （重复会报 metadata is too long）
  reference_images  [{"url":"https://...jpg"}]
  reference_videos  ["https://...mp4"]
  reference_audios  ["https://...mp3"]


四、size 对照（两列不要混用）
-------------
比例     768P（仅 768p 模型）   1080P（仅 1080p 模型）
16:9     1376x768        1920x1080
9:16     768x1376        1080x1920
1:1      1024x1024       1440x1440
4:3      1152x864        1664x1248     ← 768P 有比例加收
3:4      864x1152        1248x1664     ← 768P 有比例加收
3:2      1248x832        1728x1152     ← 768P 有比例加收
2:3      832x1248        1152x1728     ← 768P 有比例加收
21:9     1792x768        暂不建议（2560x1088 会创建失败）


五、示例
--------
POST https://snumom.com/v1/videos

768P：
{"model":"minimax_h3-768p","prompt":"人物看镜头，轻微转头","seconds":"5","size":"1376x768","reference_images":[{"url":"https://你的图.jpg"}]}

不写 seconds 时效果与上面相同（默认 5 秒）。
1080P：model 改 minimax_h3-1080p，size 改 1920x1080。

查询：
GET https://snumom.com/v1/videos/task_xxx
Header: Authorization: Bearer sk-你的Key
